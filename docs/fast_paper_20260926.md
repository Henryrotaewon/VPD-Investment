# FAST PAPER 후보 v1 — 2026-09-26

사용자 요청: 다른 모의투자와 같은 최초원금으로 10분할 시작.
VPD 현재 설정의 3,000,000원·10자리를 기준으로 독립 PAPER 계좌를 시작한다.
실거래 주문 API 및 거래소 인증정보는 사용하지 않는다.

## 자금과 대상

- 업비트 원화 전종목의 기존 FAST 수급 포착을 입력으로 사용한다.
- 최초 1자리 배분은 수수료 포함 300,000원. 매수대기 예약금을 제외한 현금을 남은 자리 수로 나눈다. 매도손익은 다음 배분에 반영한다.
- 보유 + 매수대기는 최대 10개. 조건을 채우는 종목이 없으면 현금으로 남긴다.
- 기존 관측기의 동시 15분 추적 한도 5개, 종목당 업비트 일자(09:00 KST 시작) 1회 포착을 유지한다. 10자리는 자금 보유 한도이며 매일 강제로 10개를 사는 목표가 아니다.
- 기존 관측자료를 초기화하거나 과거 포착을 소급 매수하지 않는다. 새 원장 시작 이후 발생한 새 포착만 받는다. VPD·지표가속 원장은 수정하지 않는다.

## 매매 명세

아래 수치는 연구 기초자료 `FAST_foundation.md`의 수급 A안 및 청산 후보를 고정한 **검증 가설**이다. 수익성이 입증된 운영 규칙으로 해석하지 않는다. 체결 가격 방어 수치도 이 버전의 가정이다.

| 항목 | 후보 v1 |
|---|---|
| 포착 | 완료 5분 거래대금 / 직전 10일 동일시간 평균 ≥2, 10초 거래대금 / 직전 60초의 10초 환산 평균 ≥3, 매수 주도 비중 ≥65%, 체결 ≥20건, OFI 양수. 연속 10초 구간 두 번 모두 충족 |
| 매수 의사결정 | 기존 포착 선택 순위대로 결정. 실제 처리시각을 기록하고 이후 도착한 호가에서만 체결 |
| 모의체결 | 2초 이내 신선한 체결·호가 필요. 공개 매도호가 잔량을 순서대로 소진해 수량가중 가격 산출. 한 자리 예산 전부를 체결할 깊이가 있어야 매수 |
| 가격 방어 | 슬리피지 반영 매수가가 포착 기준가 +0.5% 이내. 10초 이내 충족하지 못하면 그 포착의 매수를 제외하고 이유 기록 |
| 초기 보호선 | 포착 직전 완료 60초의 관측 저가. 신호 이후 호가가 이미 보호선을 이탈했으면 진입 취소 |
| 보호 청산 | 체결가 또는 최우선 매수호가가 보호선 이하이면 매도 결정. 다음 신선한 호가에서 가용 매수잔량으로 모의 매도 |
| 수급 청산 | 진입 이후 완료된 10초 구간 2개가 연속 순매도이고 최근 체결가가 진입 후 거래량가중 평균가격(VWAP) 아래일 때 |
| 시간 청산 | 진입 이후 고가가 3분간 갱신되지 않고 최우선 매수호가 기준 비용 차감 평가손익이 0 이하일 때 |
| 상승 추적 | 진입 이후 완료된 최근 1분봉 3개의 저가 중 최솟값으로 보호선을 상향만 함. 보호선 변경 로그 보존 |
| 비용 가정 | 매수·매도 각각 수수료 0.05%, 호가 가격에 불리한 슬리피지 0.05% 추가. 호가 스프레드·잔량에 따른 가격 영향은 별도 반영 |
| 재진입 | 종목당 업비트 일자 1회 신호. 같은 날 재진입 없음 |

고정 TP +12% / SL -6%는 승계하지 않는다. BTC 국면을 이유로 임의로 진입 기준을 변경하지 않는다.
공개 호가 기반 시뮬레이션으로 실제 주문 도달 지연·타 참여자의 잔량 소진을 완전히 재현하지 못한다. 평가는 최우선 매수호가 기준 비용 차감 추정치이며 전량 청산가격 보장이 아니다.

## 누락·재시작

- 10일 기준자료 부족: 해당 종목 신규 매수만 제외. 보유분 보호·청산 감시는 계속한다.
- 연결 단절, 파싱 불량, 지연 메시지, 프로세스 중단: 해당 종목 대기매수를 취소. 보유분은 데이터 공백을 표시하고 복구 이후 첫 유효 호가부터 청산한다. 누락 시간대의 체결가격을 만들어내지 않는다.
- 청산에 호가잔량이 부족하면 가용 수량만 부분 매도하고 다음 새 호가를 기다린다. 동일 호가 timestamp를 반복 체결에 재사용하지 않는다.
- 호가가 멈춘 동안은 이전 평가가격 및 시세 지연 표시를 유지한다. 데이터가 돌아오기 전 매도 성공으로 기록하지 않는다.
- 금전 변경과 체결기록을 SQLite 트랜잭션으로 함께 확정한다. 재시작해도 잔고를 초기화하지 않는다. 정책이 다르면 기존 원장 사용을 거부한다.

## 원장과 텔레그램

`/data/magi2/fast-observe/paper-v1.sqlite3`에 독립 자산상태, 신호·매수제외 이유, 체결, 보호선 변경, 일별 평가를 저장한다. 체결과 주요 사건만 영구 저장하고 공개 호가 원문을 복제 저장하지 않는다. 일별 평가는 업비트 일자별 한 행으로 갱신되며 지난 일자의 최종 관측 평가를 남긴다. 공백이 있었던 날은 실제 관측시각과 지연 여부를 함께 본다.

- 최상단 단독 버튼 `⚡ FAST 모의투자` / `/fast_paper`: FAST 하위 메뉴. 자산현황·포착·추적·매매기록·일별평가를 여기서 선택한다.
- `/fast_paper_balance`: 자금, 예약금, 보유, 손익. 모든 상세 화면에서 FAST 메뉴로 복귀할 수 있다.
- `/fast_paper_orders`: 최근 체결과 매수 제외 사유.
- `/fast_paper_daily`: 최근 7일 평가 기록(당일은 진행 중).
- 기존 `/fast`는 지표가속 호환 명령으로 유지. FAST는 새 명령으로 명확히 구분한다.

테스트: 10자리 예약·복리 배분, 시간 인과성, 가격·깊이 방어, 비용·부분청산 자금보존, 중복 호가 제외, 재시작·종목별 공백, 수급·시간·추적 청산, 일별 조회, 실제 관측기의 새 신호 연결을 검증한다.
