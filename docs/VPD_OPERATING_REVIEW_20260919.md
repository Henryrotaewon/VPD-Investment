## 09시 이후 재점검의 데이터 기준

업비트 거래는 계속되며 09시는 일봉과 전일 대비 기준의 전환 시각이다. 예를 들어 당일 07:30의 진행 중 일봉은 전날 09:00부터 당일 07:30까지, 당일 09시 이후의 확정 전일 일봉은 전날 09:00부터 당일 09:00까지다. 같은 일봉에 마지막 1시간 30분의 가격·거래대금이 더해지고 종가가 확정되므로 점수와 순위가 달라질 수 있다.

| 단계 | VPD 판단 자료 | 주문 판단에 함께 확인할 자료 |
|---|---|---|
| 07:30 준비 | 종료 전 일봉 | 현재 가격·유동성·기존 포지션 |
| 09시 이후 확정 | 바로 09시에 종료된 일봉과 그 이전 완성 일봉 | 현재 가격·유동성·07:30 이후 매매 내역 |

기존 스캐너는 최신 일봉을 사용한다. 따라서 그 스캐너를 09시 이후 그대로 실행하면 막 시작한 새 일봉이 들어간다. 이번 수정에서는 별도의 `magi2/closed_day_scan.py`가 09시에 종료된 자료만 선택하며 기존 MAGI1 스냅샷과 원본 파일을 덮어쓰지 않는다.

확정 스캔은 기준 시각을 당일 09:00 KST로 고정한다. API의 `to`와 반환 캔들 시각을 함께 검증하고, 새 일봉 체결 유무에 따라 배열 위치가 바뀔 수 있으므로 단순히 끝에서 두 번째 행을 고르지 않는다. 모멘텀에 쓰이는 1시간 자료도 동일한 종료 시각까지 맞춘다. 기존 스캐너의 계산 함수 5개를 부수 효과 없이 재사용하고 v1.5의 고가 기준 점수 방식을 적용한다. WPI/VWPI 부가층 전체를 재실행하는 것은 아니다. 실제 매매 가격은 별도로 현재 시세를 확인한다. [공식 조회 종료 시각 설명](https://docs.upbit.com/kr/reference/list-candles-days).

필수 구분은 다음과 같다.

- 스캔 생성 시각과 분석 대상 일봉 종료 시각을 따로 기록한다. 09시 이후 새로 생성한 확정 자료가 07시 자료의 재사용과 구별되어야 한다.
- 07:30 '거래 없음'을 추세 유효·약화 유예·자료 대기로 나눈다. 거래가 없었다는 사실만으로 모두 강한 보유 신호라고 해석하지 않는다.
- 1차와 2차는 같은 거래일 자료의 갱신이다. 두 번 눌렀다는 이유만으로 약화 유예를 두 날치 소모하지 않으며, 시간 기준 유예와 중복 실행 방지를 유지한다.
- 07:30에 이미 산 종목의 중복 매수나 작은 순위 변동에 따른 즉시 왕복 교체를 막는다. 실제 교체는 현재 매매 비용·추세·수익 보호 조건까지 확인한다.
- 09시 후 결과 보고는 '유지→약화', '약화→회복', '새 후보 편입' 등 1차 대비 변경 사유를 표시한다.

09시 확정 스캐너와 요청 후 2차 실행 경로는 구현·단위 검증을 마쳤다. 정기 예약은 추가하지 않았다. 공개 API 오류나 시간 초과 시 불완전 자료를 게시하지 않고 해당 요청의 리밸런싱을 보류한다. 스캔은 PAPER 주문 작업과 분리해 기존 손절·익절 모니터가 계속 실행될 수 있게 했다. 당일 이미 청산한 종목은 확정 재점검에서 재매수하지 않는다. 작업 환경의 실제 Upbit API 호출은 ReadTimeout으로 완료하지 못했으므로 운영 환경의 첫 공개 데이터 스캔 성공 여부는 별도로 확인해야 한다. 단위 테스트 통과를 실제 거래소 연결 성공으로 간주하지 않는다.

09:13 실행 문의를 조사했을 때에는 Railway가 이전 배포 `ee6b8d26-b493-487f-9c1d-29f13d280383`를 실행 중이었다. 09:13:20 명령 접수·09:13:23 작업 완료가 기록됐고, GitHub의 실제 최신 VPD도 07:22:08이었다. 오류나 새 홀딩 판정이 아니라 미사용 자료가 없어 반환한 결과였다.

## 왜 07:30과 현재 VPD가 맞는가

업비트 일봉 API 응답은 일봉 시작을 UTC 00:00, KST 09:00으로 표시한다. [공식 일봉 문서](https://docs.upbit.com/kr/reference/list-candles-days), [공식 API 응답](https://api.upbit.com/v1/candles/days?market=KRW-BTC&count=1).

현재 스캐너는 진행 중인 최신 일봉의 누적 거래대금을 과거 완성 일봉 평균으로 나눈다.

- `TodayValue/10`: 최신 일봉 누적 거래대금 / 이전 10일 평균 거래대금.
- `IntraAccel`: 최신 일봉 누적 거래대금 / 이전 3일 평균 거래대금.
- `VPDVelocity`: 바로 전 스캔과의 점수 차이. 보유 판단의 구버전은 시간당 변화가 아닌 원래 점수 차이를 사용했다.

| 점검 시각 KST | 일봉 시작 후 경과 | 하루 대비 시간 비율 |
|---|---:|---:|
| 07:30 | 22시간 30분 | 93.75% |
| 09:30 | 30분 | 2.08% |
| 18:00 | 9시간 | 37.50% |

이는 시간 비율이며 그만큼 거래가 발생한다는 예측이 아니다. 현재 계산을 그대로 둔 채 시각만 옮기면 시장 변화와 누적 시간 효과가 섞인다. 09시 이후 운영을 검증하려면 완성 일봉을 사용하거나, 최근 일정 길이의 구간 및 과거 동일 시간대 거래대금으로 지표를 다시 구성해야 한다. MAGI1의 기존 계산식은 변경하지 않았다.

## 하루 한 번의 한계

기존 자동 모니터는 +12% 익절·−6% 손절과 접근 경고를 처리하지만 추세 약화에 따른 보유 판단은 아침 실행에 의존한다. 아침 직후 추세가 약해지고 다음 날 첫 약화 유예를 받는 경우, 신호 약화만으로 청산하기까지 약 48시간 가까이 걸릴 수 있다. 별도 익절·손절이 먼저 발생하면 이보다 빨리 종료된다.

기존 `peak_price`는 모니터에서 계산하나 매번 저장되지 않았고 최고 수익 반납에 따른 청산도 없었다. 이번 구현은 새 최고 관측 가격을 저장하고, 정기 리밸런싱 사이에도 수익 보호 기준을 점검한다. 과거 저장되지 않은 최고 가격을 소급 복구하지는 않는다.

장중 추세 재평가는 아직 추가하지 않았다. 추가할 때에는 현재 일봉 누적 지표를 그대로 자주 호출하지 않고, 보유분의 일정 길이 구간 추세를 사용해야 한다. 점검 주기를 줄였다는 이유만으로 ‘약화 1회’의 유예가 하루에서 몇 분으로 줄어들지 않도록 시간이 명시된 정책이 필요하다.

## Q1: 보유 기준 개선 구현

새 PAPER 후보 정책은 `TREND_PROFIT_V2`다. 검증용 설정이며 실현 수익 개선이 입증된 전략은 아니다.

1. **추세 유지**: 모멘텀 ↑/↑↑이며 3일 또는 10일 평균 대비 거래대금 지지가 1배 이상일 때 보유한다. 단순한 고점 이탈 제한을 매수 압력과 같은 한 표로 더하지 않는다.
2. **수익 보호 보유**: 거래대금 지지가 약해도 상승 모멘텀이 유지되고 관측 최고 순수익이 +6% 이상인 기존 수익 포지션은 보호 기준으로 유지할 수 있다. 낮은 진입 VPD만으로 수익 포지션을 매도하지 않는다.
3. **수익 보호 청산**: 관측 최고 순수익이 +6%에 도달한 뒤 3%p 이상 반납하면 청산을 판단한다. 기존 개별 포지션의 익절·손절이 우선하며, 갭·체결 비용 때문에 해당 수익이 보장되는 것은 아니다.
4. **약화 유예**: 서로 다른 새 자료에서 약화가 2회 이상 확인되고 첫 약화부터 24시간 이상 지났을 때 청산한다. 횟수만으로 조기 청산하지 않는다. 이전 정책의 약화 횟수는 이 정책 도입 시 새 관찰 기간으로 시작한다.
5. **TOP10도 동일한 보유 심사**: 상위권이라는 이유만으로 자동 유지하지 않는다. 신규 진입은 기존 TOP10 빈자리 편입 방식을 유지한다. 새 후보와 기존 종목의 기대수익 비교·강제 교체 기능은 추가하지 않았다.

+6%·3%p·24시간은 모의 비교를 위한 초기값이다. 오늘 종목의 결과를 최적화해 선택한 값이 아니며, 운영 채택 전에 비용과 최대 손실을 비교해야 한다. 수익률은 기존 PAPER 비용 모형을 따른다. 현재 모형은 매수 슬리피지만 명시적으로 적용하고 매도 슬리피지는 적용하지 않으므로 실거래 비용 검증에 충분하지 않다.

## Q2: 판단 사유 보고 구현

완료 보고를 추세·수익 보호 보유 / 약화 유예 / 자료 대기 / 매수·매도로 나눴다. 각 종목에 VPD·순위, 모멘텀, 거래대금 근거, 순수익과 약화 평가 횟수·경과 시간을 표시한다. 예를 들면 다음과 같다.

> AWE · VPD 18 (252위) · 수익 보호 보유  
> 모멘텀 ↑ · 거래대금 0.59배 / 가속 0.25배 · 순수익 +10.20%

위 예시는 저장된 보유 상태와 스캔 가격을 조합한 표시 예제이며 실시간 평가가 아니다. 텔레그램에는 전송하지 않았다.

09-19 저장 자료에서 새 규칙의 분류는 **추세 유지 2(IO·TRAC), 수익 보호 보유 2(AWE·CFX), 약화 6**이다. 이 비교는 07:26 보유 상태와 07:22 스캔 가격을 사용한 규칙 진단이며, 같은 시각의 체결 재현이나 수익률 백테스트가 아니다. 첫 적용에서는 약화 6종목도 곧바로 청산하지 않는다.

- 우선 4주 이상 전향 모의 비교로 결함을 확인하되, 그 기간만으로 수익성이 검증됐다고 선언하지 않는다. 상승·하락·횡보 구간별 표본과 별도 평가 구간을 확보한다.
- 현재 일중 스냅샷은 불규칙하고 선택 시각에 편중되어 있어 모든 운용 시각의 공정한 수익률 비교를 지원하지 않는다. 과거를 재구성할 때는 당시 미완성 일봉·상장 종목군을 재현하고 미래 종가·최고가를 쓰지 않는다.
