# BASIS 현물·선물 차익전략 준비안 v1

2026-09-19 KST · `basis-plan-v1` · 실제 배정자금 0 · 실주문 OFF.
코인 현물·선물 전략으로 정의한다. 현물 매수와 동일 코인 수량의 선물 매도를
묶으며, WAVE/FAST 방향성 매매와 원장·자금·검증을 분리한다.

후속 확장: 동일 거래소 v1은 비교 기준선으로 유지하며, 전체 연구 범위는
[크로스마켓 연구](CROSS_MARKET_RESEARCH.md)의 거래소 간 현선물·펀딩·현물 재고
차익과 WAVE 통합 관측으로 넓혔다. v1의 동일 거래소 제한을 해제해 그 실행
모델을 곧바로 다른 거래소에 적용하는 방식은 사용하지 않는다.

## 두 가지 수익 원천

| 전략 | 목적 | 진입 기준안 | 보유·청산 |
|---|---|---|---|
| BASIS-DATED | 만기 선물의 양의 가격차 수렴 | 만기 7~90일, 실제 선물 매도호가−현물 매수호가 >0, 비용 차감 총자본 수익률 ≥0.50% 및 단순 연환산 ≥5% | 만기 결제/현물 청산 또는 가격차 조기 수렴 시 함께 종료 |
| BASIS-PERP | 현물 보유·무기한 선물 숏의 펀딩 수취 | 최근 7일 양의 펀딩 비율 ≥75%, 보수적 24시간 총자본 순수익 ≥0.10% | 펀딩 전 재평가, 최대 72시간에 종료·재검토 |

수치는 가설이며 현재 시장에서 이 조건의 기회가 존재한다고 확인한 것은 아니다.
연환산은 단순 비교용 `기간 순수익률×365/일수`, 재투자·지속 수익 보장이 아니다.
무기한 선물에는 만기 수렴 의무가 없으므로 만기형 확정 차익처럼 계산하지 않는다.

우선 연구 대상은 동일 거래소 BTC/ETH 현물과 **동일 결제통화의 선형 선물**이다.
바이낸스 공개 데이터 인터페이스를 참고했으나 사용자 계정의 파생상품 이용·상품
제공 여부를 확인하거나 주문 권한을 연결한 것은 아니다. 실제 가능한 계약 목록·
상태·만기·승수·가격/수량 단위·결제지수는 상품 메타데이터로 확인해야 한다.
COIN-M/역선형, 차입 현물 매도+선물 매수의 역방향, 계좌 간 포트폴리오 마진은 v1 제외.

업비트 KRW 현물+해외 USDT 선물 조합은 별도 확장안이다. BTC 가격 노출을
일부 상쇄해도 KRW/USD(T) 환율·김치프리미엄·서로 다른 결제가격과 담보 이동
제약이 남는다. 예치된 국내 현물 평가이익이 해외 선물 증거금으로 자동 전달되지
않는다. 따라서 국내외 차익을 동일 거래소 BASIS 성적과 합산하지 않는다.

## 손익과 투입자본

선형 계약에서 같은 기초수량 Q를 매수/매도한 경우:

`가격손익 = Q×(현물 청산−현물 진입) + Q×(선물 진입−선물 청산)`

`순손익 = 가격손익 + 실제 받은 펀딩 − 낸 펀딩 − 4개 매매의 수수료 − 기타 자금비용`

`총투입자본 = 현물 매수금 + 진입 수수료 2개 + 초기 선물 증거금 + 여유현금`

현물 ask/선물 bid로 진입하고 현물 bid/선물 ask로 청산하는 깊이 VWAP를 사용한다.
체결가격에 스프레드/슬리피지가 이미 들어 있다면 또 차감하지 않는다.
코인 가격이 상승해 선물에서 손실이 나더라도 현물 수익과 합산해 쌍 전체를 평가한다.
정산기준과 현물 청산가격이 다르면 만기에 가격차가 완전히 소멸한다고 가정하지 않는다.

초기 연구의 자금은 선물 명목액 100% 이상의 증거금 + 명목액 20% 이상의
여유현금을 현물 매수금과 별도로 준비한다. 차입은 없다. 이는 약 1배 수준의
선물 담보 가정이며 청산을 없애는 구조는 아니다. 담보가 분리되어 있으면
현물 이익이 있어도 선물 청산 위험이 발생할 수 있다. 투입자본이 대략 현물
한쪽 금액의 2.2배이므로 수익률을 현물 금액만으로 계산해 부풀리지 않는다.
기존 FAST+WAVE 4.9% 준비 예산을 BASIS에 중복 사용하지 않는다.

## 펀딩을 과대 추정하지 않는 방법

- 예정 펀딩시각·간격은 계약별 메타데이터에서 읽는다. 항상 8시간이라고 고정하지 않는다.
- 최근 7일의 확정 지급 이력으로 양의 비율을 계산한다. 지급 횟수만큼 독립
  매매 기회가 있었다고 세지 않는다. 지급일정 변경과 누락을 구별한다.
- 양의 지급률 예상은 과거 양의 중앙값과 현재 양의 예상률 중 작은 값의 50%만 인정.
  음의 예상률은 100% 비용으로 반영. 향후 일정별 명목액 변화도 보수적으로 추정한다.
- 현재 음의 예상률이면 신규 PERP 진입은 보류한다. 남은 펀딩 수입만으로 진입을
  정당화하지 않고 24시간 이후 청산 가격차가 현재보다 30bps 악화되는 상황을 반영한다.
- 4회 매매 비용·예상 체결 충격·담보 기회비용을 모두 차감하고도 순수익 기준을
  넘는지 본다. 실제 펀딩 수익은 지급시각의 보유/정산 내역으로만 확정한다.
- 직전 또는 현재 펀딩률 하나에 횟수를 곱한 값을 확정 연수익률로 제공하지 않는다.

## 두 주문을 하나의 거래로 관리

`IDLE → BOTH_RESERVED → PAIR_PENDING → HEDGED → PAIR_EXIT_PENDING → CLOSED`

단일 거래소에서도 현물·선물 주문을 원자적으로 동시에 체결할 수 있다고 가정하지 않는다.
두 주문 의도와 부모 pair_id를 먼저 원장에 저장한 뒤 가격을 제한한 IOC 쌍을 준비한다.
선물 실제 코인 수량은 계약 수×승수로 환산하며 주문 금액을 같게 맞추는 것과 다르다.
양쪽 수량 단위에 맞는 공통 수량을 선택하고 최소 주문·계약단위를 다시 검사한다.

양쪽 확정 체결 수량 오차는 0.1% 이내가 목표다. 초과분이 있으면 2초 이내
허용가격 안에서 부족한 쪽을 맞추고, 불가능하면 초과 체결된 쪽을 축소한다.
부분체결된 공통 수량은 유지할 수 있지만 남은 주문의 취소 완료를 확인해야 한다.
어느 한쪽 응답이 불명확하면 우선 `UNKNOWN → RECONCILE_BOTH_LEGS`;
반대 주문을 무작정 추가해 더 큰 노출을 만들지 않는다. 계좌 전체 신규 진입도 멈춘다.
청산 시 선물 close/reduce-only의 지원 방식은 실제 포지션 모드에 맞춰 확인한다.
재시작 뒤에도 pair_id·양쪽 주문·잔고·지급 펀딩을 대사한 후 재개한다.

## 보유 중 조기 축소·청산 기준안

- 쌍 전체의 실현+청산 가능 평가손익이 투입자본 대비 −0.50% 도달.
- 숏의 mark price와 청산가격 거리 `(청산가격−mark)/mark` <30%.
- 유지증거금/가용 마진잔고 ≥30%, 또는 평가 증거금/현재 선물 명목액 <75%.
- 펀딩이 음수로 전환되면 다음 지급 전에 남은 기대 수입과 즉시 청산비용을 재평가.
- 가격차 수렴으로 남은 기대 순익이 청산·자금비용 이하, 계약 변경/비정상 마크가격,
  담보/거래소 상태 이상은 신규 진입 중단 및 축소 판단.

이 기준들은 향후 쌍 실행기에서 강제해야 한다. 현재 코드는 손익 계산·진입 준비
체크·헤지 불일치 상태 조언까지만 제공하며 모니터링/청산 루프는 없다.

## 데이터·검증·보고 준비

전 종목 대신 BTC/ETH와 선택 계약만 대상으로 현물/선물 양방향 호가, 동기화
시각·깊이, mark/index, 펀딩 예정/실제, 계약 메타, 최소수량, 계좌별 수수료,
증거금·유지증거금·청산가격이 필요하다. 공개 수집은 아직 시작하지 않았다.
새 파생 주문 API/키도 연결하지 않았다.

사전 검증안: 최소 30일 관측, 쌍 거래 50회, 미사용 검증 구간 14일. 만기형은
미사용 만기 2회 이상을 실제 결제 과정까지 관찰해야 하며 30일만으로 끝나지 않을 수 있다.
같은 지급구간을 재사용한 펀딩 표본을 독립 거래처럼 세지 않는다.
기간/자본 가중 순손익·최대 낙폭·가격차 확대·음의 펀딩·증거금 급증·부분체결·
UNKNOWN/재시작·거래소 정지 시나리오를 검증한다. 50회나 30일 자체는 승인 근거가 아니다.

보고서 준비 구조: pair_id / 종류 / 현물+선물 거래소·계약 / 기준·체결 가격차 /
기초 수량·순델타 / 총투입자본 / 현물손익 / 선물손익 / 펀딩 / 수수료 /
합산 순손익·수익률 / 증거금 여유 / 만기·다음 펀딩 / 진입·청산·대사 상태.
기존 자산 통합 보고에는 선물 한쪽 손익을 현물 손익과 중복 합산하지 않으며,
선물 계좌 조회와 쌍 원장이 구현된 후 함께 연결한다.

## 이번 산출물

- `basis_policy.json`: 버전별 기준안, 실제 배정자금 0.
- `basis_plan.py`: 비용 포함 쌍 손익 계산, 헤지 불일치 판정, 보수 시나리오 입력 검사.
- `assess_basis_setup`은 별도 엔진이 만든 시점별 보수 경제성 시나리오를 입력받는다.
  비용/펀딩 모델의 타당성을 직접 증명하지 않고, 통과도 `RESEARCH_CANDIDATE`일 뿐이다.
- 전략검증 → `BASIS · 현선물 준비`: 읽기 전용 설명. 버튼으로 주문·모의를 시작하지 않는다.
- 파생상품 자금 투입·주문 실행·새 계좌 권한 추가는 이번 준비에 포함되지 않는다.
