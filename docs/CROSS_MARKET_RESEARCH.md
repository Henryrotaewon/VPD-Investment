# MAGI 크로스마켓 전략 검토와 WAVE 확장

2026-09-19 KST · `cross-market-research-v1` · 문헌·구현 검토 및 연구 준비.

분석 범위를 **거래소 × 현물/무기한/만기 × 기초자산 × 결제통화**로 확장한다.
앞서 만든 동일 거래소 BASIS v1은 실행 복잡도를 비교할 기준선이다. 전체 연구를
동일 거래소에 한정하지 않는다. WAVE는 이 지도에서 신호와 유동성의 전파를 보고,
MAGI2는 그 결과를 FAST·방향성 WAVE·차익/캐리 전략에 각각 적용해 검증한다.

## 해외 근거와 적용 판단

아래 문헌/공식 구현의 존재는 MAGI 환경에서의 수익성이나 거래 가능성을 증명하지 않는다.
표의 우선순위와 적용 방식은 문헌에서 출발한 **본 프로젝트의 판단**이다.

| 계열 | 확인한 근거 | MAGI에 적용할 부분 | 우선순위·남는 문제 |
|---|---|---|---|
| Lead–lag / cross-impact | Albers 외의 Bitcoin 시장 간 선행·후행 및 거래비용 연구 [1] | 현물→현물, 선물→현물, 현물→선물 전파를 따로 추정 | 1순위. 논문의 500ms 결과를 우리 1초 목표 판단·네트워크 지연에 전용하지 않음 |
| Cross-venue cash-and-carry / basis convergence | BIS Crypto carry [2], Hummingbot spot-perpetual 구현 [3] | A 현물 매수·B 선물 매도, 과도한 가격차의 수렴/펀딩 평가 | 2순위. 자금 분리·증거금 급증·정산가격 차이·비용 반영 |
| Cross-exchange funding spread | Hummingbot 공식 펀딩 차익 예제 코드 [4] | A 무기한 롱·B 무기한 숏, 같은 보유기간의 순지급 비교 | 2순위. 지급주기·명목액·청산 가격차가 다르므로 단순 펀딩률 차감 금지 |
| Cross-exchange spot inventory | [3][5]의 복수 시장 가격·체결·잔고 관리 구조를 현물 쌍으로 응용 | A 현금과 B 코인을 미리 배치해 저가 매수·고가 보유분 매도 | 2순위. 재고 회복 비용과 단방향 소진까지 포함해야 반복 가능 |
| Calendar / term spread | [2]의 현물·선물 carry 구조를 다른 만기 비교로 확장 | 만기별 상대 프리미엄과 무기한 펀딩을 함께 관측 | 3순위. 동일 자산이어도 만기·정산·승수가 달라 1:1 현물처럼 계산 불가 |
| Cross-exchange market making, XEMM | Hummingbot 공식 XEMM [5] | A 지정가 체결 후 B 헤지, WAVE 급변 때 낡은 호가 취소/축소 | 3순위. 대기순번·취소 지연·역선택·헤지 실패 검증이 먼저 |

[1]은 거래소 간 영향과 비용을 함께 연구한다. 방향 예측 지표가 존재하는 것과
사용자 환경에서 실제 체결 후 이익이 남는 것은 별도다. [2]는 높은 carry에도
자금 제약과 증거금·청산 위험이 있음을 보여준다. [3]은 두 시장의 괴리 진입·수렴
청산 구조를 문서화하지만, 해당 V1 페이지에는 Maintainer가 None으로 표시된다.
설계를 참고하며 외부 코드를 그대로 설치하거나 기본값으로 운용하지 않는다.

[4]는 지급주기를 시간당으로 정규화해 비교하는 구현 예시다. MAGI는 이를 더
구체화해 **실제 예정 지급시각을 보유구간 안에서 합산**하고, 체결·청산 가격차까지
별도로 평가한다. 예제의 수익률·레버리지·목표값을 복사하지 않는다.

## WAVE를 공통 관측 지도로 사용

노드는 `venue, asset_id, kind, symbol, quote, settlement, expiry`로 식별한다.
`Binance BTC` 하나로 현물과 선물을 섞거나 같은 티커의 다른 자산을 합치지 않는다.
계약 승수·선형/역선형·최소수량·가격단위·거래상태는 검증된 메타데이터로 붙인다.

| 관계 | 관측 질문 | 활용 후보 |
|---|---|---|
| 현물 A → 현물 B | 충격이 반복적으로 먼저 잡히고 B에서 추가 반응하는가? | WAVE 진입, FAST의 전파 확인 필터 |
| 선물 A → 현물 B | 레버리지 시장의 움직임이 현물에서도 거래 참여 증가로 이어지는가? | 지속 상승과 일시 과열 분리 |
| 현물 A → 선물 B | 실제 현물 수요 뒤 선물이 지연 반응하는가? | 방향성/베이시스 상태 판별 |
| 현물 A ↔ 선물 B | 비용 대비 가격차가 크고 이후 수렴하는가? | CROSS_BASIS |
| 무기한 A ↔ 무기한 B | 동일 보유기간 동안 어느 쪽에서 실제 펀딩을 더 받는가? | CROSS_FUNDING |
| 국내 KRW ↔ 해외 USD(T) | 환율·스테이블코인 가격을 반영하고도 괴리가 남는가? | 국내외 프리미엄, 차익/헤지 별도 검증 |

경로는 과거 성공률만으로 한 방향으로 고정하지 않는다. 상승/하락·시간대·변동성·
유동성·상품 조합별로 다시 검증한다. 전파 시간은 원천시각과 수신시각/시계 품질을
함께 보고, 확인 시점 이후의 남은 수익 가능 구간을 평가한다.

OI 증가는 신규 매수 우위와 같은 뜻이 아니다. 새 롱과 숏이 함께 생기며 가격·
공격적 체결 방향·펀딩·청산 자료가 필요하다. 가격 상승+OI 감소도 숏 청산의
가능성을 검토하는 단서일 뿐 청산 원인을 확정하지 않는다.

WHALE은 별도 보조 특징이다. 소유자/거래소 입출금 방향이 확인되지 않은
대규모 전송을 가격 충격의 촉발지로 연결하지 않는다.

## WAVE를 전략에 연결하는 네 가지 가설

1. **확산 지속**: 여러 독립 시장에 같은 방향 반응이 늘고 목적지 유동성이 유지된다.
   FAST 단독 대비 WAVE 확인을 추가한 진입의 순손익이 개선되는지 비교한다.
   모든 FAST 기회를 WAVE 확인까지 기다리게 바꾸지는 않는다.
2. **국소 괴리**: 한 시장의 상대 가격만 벌어지고 다른 시장의 유효 가격은 안정적이다.
   재고·담보·비용이 허용되면 쌍 거래 후보. 가격차가 지속될 구조적 이유도 검토한다.
3. **레버리지 과열**: 현선물 차이·펀딩·OI/체결 압력이 평소 범위를 벗어난다.
   carry 후보인 동시에 증거금/급변 위험 상태다. 높은 펀딩 하나로 진입하지 않는다.
4. **청산 연쇄 또는 관측 불량**: 급격한 주문흐름 변화·깊이 감소·피드 공백이 생긴다.
   새 진입은 보류하고 보유 포지션의 청산 가능성과 담보 여유를 먼저 본다.

이는 아직 분류 모델이나 검증된 확률이 아니다. 상태별로 비용 차감 성과가
개선되는지 시간순 검증을 거쳐야 하며, 라벨을 사후 손익에 맞춰 붙이지 않는다.

## 거래소 간 차익을 계산하는 기준

### 사전 자금 배치와 계좌별 담보

초단기 신호를 잡은 뒤 코인을 송금해 반대쪽에 도착하기를 기다리지 않는다.
A 현금/B 코인 또는 A/B 증거금을 미리 배치한다. 이체는 별도 재고 회복 단계다.
출금 중단·네트워크 비용·전송 소요·입금 확인·한도·환전 비용과 자금 기회비용을
재고 회복 가능성에 포함한다. 반복 불가능한 1회 재고 교환을 반복 수익으로 계산하지 않는다.

거래소 A의 평가이익은 거래소 B의 증거금 여유가 아니다. 양쪽 마진·청산가격을
각각 모니터링하고 총자본 분모에 모두 넣는다. 양쪽 체결은 원자적이지 않으므로
pair_id, 개별 주문 ID, 부분체결, UNKNOWN 대사와 비상 노출 축소가 필요하다.

### 가격과 통화

동일 기초수량의 매수 ask VWAP와 매도 bid VWAP를 비교한다. 전광판 현재가,
mark/index를 체결가로 쓰지 않는다. 수량이 다르면 이 비교의 결과를 내지 않는다.
최초 측정 품질안은 호가 나이 ≤1.5초·양쪽 시각 차이 ≤0.5초. 이 조건은
초단기 선행성 입증 기준이 아니며 실제 네트워크 측정 결과로 조정해야 한다.

KRW로 비교할 때 매수에 필요한 USD(T)는 환전 ask, 매도 대금 환산은 bid를
사용한다. USD=USDT=USDC=1을 가정하지 않는다. 환산은 보고용 비교일 뿐
실제 환전 가능성이나 FX 헤지가 확보됐다는 의미가 아니다.
현선물 가격차가 양수여도 청산 시점의 잔여 베이시스·펀딩·4회 매매 수수료·
담보 및 재고 회복 비용이 빠져 있어 그 값을 예상 순이익으로 표시하지 않는다.

### 펀딩 시간 정렬

예: A 롱은 매시간 0.01% 지불, B 숏은 8시간마다 0.05% 수취한다고 가정한다.
명목액이 둘 다 1,000 USDT이고 해당 지급을 전부 거친다면 8시간 동안
A −0.8, B +0.5로 **순펀딩 −0.3 USDT**다. 큰 단일 지급률이 유리한 전략을
뜻하지 않는다. 이 수치는 합성 예시이며 현재 거래소의 실제 펀딩률이 아니다.

`funding_cashflow`는 `(진입시각, 종료시각]` 안의 명시적 지급 이벤트를 합산한다.
SCENARIO는 시점별 명목액×예상률×방향, ACTUAL은 확정된 실제 정산 현금으로
계산하며 두 종류를 섞지 않는다. 지급 직전 진입의 정산 자격은 거래소 응답으로
확인한다. 같은 결제통화만 합산하고 다르면 별도 FX 현금흐름 모델이 필요하다.

## 현재 자료로 가능한 것과 추가할 것

코드 확인 기준, MAGI1 `public_ws.py`는 6거래소 **현물**을 수집한다.
`runner.py:derivatives_loop`는 Bybit linear ticker를 약 1분 간격으로 조회해
OI·펀딩·mark/last를 보조자료로 저장한다. 이는 양방향 선물 호가·체결 피드가 아니며
선물에서 시작되는 초단기 WAVE의 검증에는 부족하다. 이번 점검은 코드 범위 확인이며
각 피드의 최신 정상 수신 상태를 새로 확인했다는 뜻은 아니다.

준비 단계별 구현:

1. 기존 현물 관측망을 재사용. 동일 자산 BTC/ETH의 Binance/Bybit 선형 상품
   메타데이터와 공개 호가·체결·mark/index·펀딩 예정/실제부터 별도 어댑터로 준비.
   제공 상품/이용 가능 여부는 연결 때 확인. 만기 계약이 없으면 임의 생성하지 않는다.
2. 연구용 관측에서 경로·상품·방향·시간대별 독립 사건과 비사건 관측 범위를 기록.
   현물 기존 사건과 선물 사건을 같은 사건으로 소급 결합하지 않는다.
3. FAST 단독, FAST+현물 WAVE, FAST+현선물 WAVE를 같은 후보/기간으로 비교.
   별도로 CROSS_BASIS/CROSS_FUNDING/현물 재고 교환의 모의 원장을 구성한다.
4. XEMM/만기 상대가치는 호가 순번·체결률·담보 복구를 확보한 후 확장한다.
   다른 코인 간 페어 트레이딩은 동일 자산 헤지가 아니므로 별도 모델이 필요하다.

추가 수집은 이번에 시작하지 않았다. 전 종목 원본 호가를 늘리지 않고 대상 상품의
짧은 메모리 관측과 1초/5초 특징 요약, 사건 전후 제한 자료, 지급·체결 로그를
저장하는 구조로 설계한다. 기존 MAGI1 수집·스키마·보관 설정을 변경하지 않는다.
MAGI3에는 새 파생 주문 연결·자금 배정이 없다.

## 검증에서 빠뜨리지 않을 항목

- 기존 WAVE 사후 사건 목록의 선택 편향을 독립 트리거/비사건 관측으로 보완.
- 경로 수가 늘수록 우연히 좋아 보이는 조합도 증가하므로 탐색/검증 구간 분리,
  날짜·충격 군집의 중복 제거, 다중 비교를 반영한 불확실성 평가.
- 미래 정보가 들어간 가격/베타/정규화 기준 금지. 장세·시간대·유동성을 맞춘 대조군.
- 의사결정+주문+헤지 지연 뒤 호가로 재생. maker 주문은 호가 접촉만으로 체결 처리 금지.
- 비용·환전·청산 가격차·펀딩 부호/지급시각·양쪽 담보·재고 회복까지 반영한 손익.
- 수익률 외에 자본 점유시간, 거래소별 최대 손실, 미헤지 노출 시간·금액,
  부분체결/UNKNOWN·체결 거절·관측 불가 비율을 보고.
- 보유 장기화/담보 악화/시장 분리 시나리오. 높은 펀딩·큰 괴리를 자동 고신뢰 신호로 만들지 않음.

## 이번 반영 범위

- `cross_market_policy.json`: 6개 전략 계열·연구 우선순위·시장 구분·측정 품질안.
- `cross_market.py`: 상품 식별, 수량/시각/환율을 확인한 가격차, 지급일정별 펀딩 계산.
  이 함수들은 순수 오프라인 연구 보조 함수이며 운영 수집/전략 루프와 미연결이다.
- 전략검증과 WAVE 하위의 **크로스마켓 연구** 읽기 전용 버튼.
