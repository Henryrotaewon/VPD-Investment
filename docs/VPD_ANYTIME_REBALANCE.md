# VPD 요청 시점 리밸런싱

2026-09-19: 07:20~08:30 진입 제한과 09시 고정 자료 재사용을 요청 시점 스캔으로 대체한다. MAGI2 PAPER에만 적용한다.

## 처리 흐름

1. 사용자가 Telegram 리밸런싱 실행을 확인하면 요청 시각을 KST 분 경계로 내린다. 15:42:35 요청은 15:42:00을 기준으로 한다.
2. 업비트 KRW 전 종목의 자료를 이 경계에 고정해 조회한다. 전일 이전은 완료 일봉, 당일은 완료 시간봉과 마지막 시간의 완료 분봉을 합쳐 사용한다. 진행 중인 일봉을 순차 조회해 종목별 기준 시각이 달라지는 문제를 피한다.
3. 09:00 정각 경계에서는 전일 확정 일봉을 사용한다. 09:01 이후에는 새 당일 누적 흐름이 반영된다. 자정 전후에도 거래일 시작은 09시다.
4. 하나의 `vpd_rebalance.json`에 TOP10과 전체 순위를 원자적으로 기록한다. 보유 종목 판단에 다른 시각의 CSV를 섞지 않는다.
5. 별도 스캔 작업 중에도 기존 보유분 모니터가 계속된다. 스캔 후 기존 PAPER 작업이 끝나면 현재 포트폴리오를 다시 읽고, 요청했던 스냅샷으로 한 번 재평가한다.

같은 분의 중복 요청은 같은 자료를 사용하고 이미 평가했으면 매매하지 않는다. 새 분의 요청은 새 스캔을 수행한다. 진행 중 중복 리밸런싱과 종목 리필은 합류시키거나 차단한다. 당일 청산 종목은 재진입하지 않는다. 보유 신호 약화는 서로 다른 관측 2회와 실제 24시간 경과가 모두 필요하다.

## 데이터와 실패 처리

- 기존 v1.5 기본 VPD 점수와 모멘텀 공식, 35봉 워밍업을 공유한다. 일봉 20개 미만·전일 봉 없음·거래량 기준 없음은 제외 사유를 저장한다. VWPI/WPI 추가 점수는 이 요청 스캔에서 재계산하지 않는다.
- `1H%`는 요청 시각 이전에 완료된 인접 시간봉 간 수익률이다. `hour_return_asof`에 기준을 표시한다.
- 거래 없는 구간은 거래를 만들어 내지 않는다. 당일 거래가 전혀 없으면 전일 종가와 거래량 0으로 계산한다.
- 거래대금 지표는 해당 시각까지 누적값이다. 09시 직후의 값은 작을 수 있으며 일중 경과시간 보정이나 수익성 최적화를 추가한 변경은 아니다.
- 4개 조회 작업이 하나의 6.25회/초 제한을 공유한다. 429·서버 오류·연결 지연은 최대 3회 시도한다. 전체 조회 제한은 480초, 실행 자료 유효시간은 기준 시각부터 600초다.
- 일부 API 요청 실패 시 전체 스캔을 보류하고 기존 파일을 덮어쓰지 않는다. 요청 시각 불일치·만료·필수 보유 데이터 누락 시 해당 리밸런싱은 매매하지 않는다.
- 모의 체결가는 실행 시점에 별도로 조회한다. 스캔 기준 시각 가격으로 소급 체결하지 않는다.
- `REBALANCE_FINISHED` 원장 이벤트, `last_rebalance_result`, 종목별 판단과 로그에 기준 시각을 남긴다.

## 승인된 운영 요청 한 번 실행

`MAGI2_REBALANCE_ONCE`에 `{"id":"고유한_ASCII_ID","expires_at":"시간대가_있는_ISO8601"}`를 설정하면 다음 정상 기동에서 같은 스캔·리밸런싱 경로를 한 번 요청한다. 사용자가 명시적으로 요청한 PAPER 실행용이며 일반 기동에서 자동으로 설정하지 않는다.

- 만료까지 24시간 이하인 유효 요청만 받는다.
- 영구 볼륨의 `rebalance_requests.json`에 ID를 먼저 기록한 뒤 실행한다. 재기동 시 같은 ID를 재실행하지 않는다.
- 시작 직후 장애가 나도 자동 재시도하지 않는 at-most-once 요청이다. `claimed`, `executing`, `completed`, 실패 상태를 구분하며 실제 매매 결과는 원장과 `last_rebalance_result`로 확인한다.
- 소스·이 변수 외 서비스, API 키, 볼륨, MAGI1 원천 데이터, MAGI3 주문 경로는 변경 대상이 아니다.

## 확인 근거

- [업비트 분 캔들 조회](https://docs.upbit.com/kr/reference/list-candles-minutes): 거래가 없는 구간에는 캔들이 생성되지 않으며 `to` 이전 캔들을 조회한다.
- [업비트 일 캔들 조회](https://docs.upbit.com/kr/reference/list-candles-days): 일봉 조회와 종료 시각 규격.
- [업비트 요청 수 제한](https://docs.upbit.com/kr/reference/rate-limits): 캔들 그룹은 IP 기준 초당 10회 한도를 공유한다.

테스트는 24시간 요청, 자정·09시 경계, 완료되지 않은 봉 배제, 분/시간봉 중복 합산 방지, 이전 스냅샷 혼합 방지, 실패 시 파일 유지, 동시 모니터, 중복 요청·당일 재진입 방지, 운영 요청 재기동 중복 방지를 검증한다.

## 전량 교체 (`/rebuild`)

VPD 모의투자 메뉴에 별도 **전량 교체** 버튼을 제공한다. 조회 또는 배포로는 실행하지 않으며, 권한이 있는 사용자가 60초 내 **전량 매도 후 재매수** 확인 버튼을 눌렀을 때만 요청한다.

| 기능 | 보유 종목 | 신규 구성 |
| --- | --- | --- |
| 리밸런싱 `/morning` | 추세·수익 보호·약화 유예 규칙으로 유지/매도 | 빈자리만 최신 후보로 매수 |
| 종목 리필 `/refill` | 기존 보유 유지 | 빈자리만 매수 |
| 전량 교체 `/rebuild` | 기존 보유 전량 모의 매도 | 매도 후 예수금 전액으로 최신 VPD TOP10 균등 매수 |

전량 교체는 요청 시점 새 스캔 경로를 공유하지만 보유·약화 유예와 당일 재진입 제한을 명시적으로 해제한다. 기존 보유와 새 TOP10이 겹치면 해당 종목도 매도하고 새 가격에 다시 매수한다. 이 동작과 모의 비용은 확인 화면에 안내한다. 서로 겹치지 않는 종목만 찾는 기능은 아니다.

- 최초 원금, 과거 실현손익, 누적 성과와 기존 원장을 보존한다. 신규 가상원금을 지급하거나 계정을 초기화하지 않는다.
- 기존 모형과 동일한 매도 수수료, 매수 수수료·슬리피지를 반영한다. 매도 슬리피지는 기존 모형과 마찬가지로 별도 반영하지 않는다.
- 후보 TOP10이 모두 준비되어야 하며, 기존 보유와 신규 후보의 모든 현재가·수량·원가·비용 설정을 먼저 검증한다. 하나라도 부족하면 매도 이전에 전체 작업을 보류한다.
- 일반 리밸런싱과 전량 교체는 동일 주문 작업자를 공유한다. 스캔 중 보유 모니터는 유지되고, 리필·리밸런싱·전량 교체가 겹치지 않는다.
- 같은 스냅샷으로 전량 교체를 반복하지 않는다. 일반 리밸런싱 직후 동일 자료에 대한 첫 전량 교체는 명시적 재구성 요청으로 허용한다. 전량 교체 후 같은 자료의 일반 리밸런싱은 건너뛴다.
- 매도 사유 `VPD_FULL_REBUILD`, 신규 세션 `FULL_REBUILD`, 기준 시각과 개별 `event_id`를 원장에 남긴다. 중복 편입 종목의 기존 포지션도 `closed_positions`에 보존한다.

### 저장 중 장애

매매 계획 전체를 복사본에서 계산한 뒤 단일 PAPER 작업자가 `paper_rebuild_pending.json`에 승인된 계획과 원장 이벤트를 기록한다. 상태와 원장은 임시 파일 교체로 저장하며, 기존 상태의 해시가 달라졌으면 덮어쓰지 않는다. 상태/원장 저장 도중 중단되면 다음 상태 로드에서 승인된 같은 계획의 저장을 완료한다. 이벤트 ID로 원장 중복을 방지한다. 이 복구는 PAPER 상태 저장 절차이며 실주문 재전송이 아니다.

검증 항목: 전량 청산과 새 구성, 동일 종목 재편입, 비용·원금·누적 손익·원장 보존, 데이터 누락 시 무변경, 같은 자료 중복 방지, 운영자 확인·권한, 스캔 후 올바른 실행 모드, 저장 각 단계의 장애 복구.
