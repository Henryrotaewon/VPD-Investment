# FAST 지표 교체 준비 — 2026-09-25

상태: 계산 모듈·공개 API 어댑터·SHADOW 관측 도구 구현. 자동 종목 선정과 PAPER 매매 연결 전 단계다.
기존 MAGI1 FeatureEngine/WAVE 원천·분석 스키마는 수정하지 않는다.

## 운영 FAST 초기화

9월 23일 초기화 뒤 기존 TOP5 자동시작 예약으로 구전략 기록이 다시 쌓였다.
PR #51은 초기화 ID를 `fast-wave-indicator-prep-20260925-v2`로 바꾸고 자동시작 예약을 제거한다.
삭제 대상은 기존 FAST `fast_paper.sqlite3`, `fast_evidence.sqlite3`와 각각의 WAL/SHM뿐이다.
VPD 원장, MAGI1/WAVE 기록과 MAGI3 원장은 대상이 아니다. 마커가 동일하면 재시작 시 재삭제하지 않는다.
초기화 직후 거래소별 100만원, 총 400만원으로 재설정하며 신규 포착·매매는 정지한다.
이 초기화 수정은 배포 완료. 새 지표 모듈은 별도 준비 브랜치다.

## 판단 정의

| 항목 | 정의 |
| --- | --- |
| 완료 일봉 | 최소 100개, 기본 조회 120개. UTC 00:00(한국 09:00) 기준 연속 일봉 |
| MACD | EMA 12/26, 시그널 9의 히스토그램. EMA는 SMA seed. 전일종가로 bps 정규화 |
| RSI | Wilder 방식 14기간 |
| Williams | 14기간 %R |
| 거래량 | 현재 누적 거래량 ÷ 경과 일 비율 ÷ 직전 20일 거래량 중앙값 |
| 전일 변화 | 미완성 당일봉 지표 − 완료 전일봉 지표 |
| 장중 속도 | 최근 두 관측의 지표 변화 ÷ 실제 경과 분 |
| 장중 가속도 | 최근 두 속도의 차이 ÷ 두 구간 중간시점 간격(분² 기준) |

최소 5분 경과 후 3개 관측이 필요하다. 기본 관측 간격은 60초이며 30~180초 간격만 허용한다.
전일 대비 변화와 장중 가속도를 따로 계산한다. 시간 간격이 다른 값을 단순 2차 차분하지 않는다.
완료봉은 당일 동안 고정하고, 거래소가 전일봉을 수정하면 캐시를 버리고 재준비한다.
누락 일봉은 임의로 채우지 않는다. 새 상장·거래 없는 날이 있는 종목은 후보에서 제외될 수 있다.
미완성 당일봉을 전일 기준에 포함하지 않는다.

점수: 상승+가속 지표당 25점, 상승만 확인되면 10점. 기본 후보 조건은 65점 이상,
4개 중 3개 이상 상승·2개 이상 가속·거래량 속도 상승이다. RSI 78 이상 또는 Williams -8 이상은
초기 과열 제외 조건이다. 모든 임계값은 연구 가설이며 적중확률·수익률을 의미하지 않는다.

수급 확인은 기존 공개 체결 표본 구조를 재사용한다: 매수 주도 거래대금 70% 이상,
20체결 이상·5초 이상 표본, 최신 체결/수집 시각 3초 이내, 스프레드 10bps 이하.
지표 후보와 수급 확인을 모두 통과하면 `paper_candidate=true`를 기록한다. 이 값은 주문을 발생시키지 않는다.
MACD·RSI·Williams는 가격 기반 지표로 서로 상관되어 있고 선행성을 보장하지 않는다.
거래량 환산은 선형 추정이며 시간대별 계절성 보정이 없다. 이를 검증 전 수익 모델로 해석하지 않는다.

## 입력·저장·실행

지원 어댑터: 업비트 KRW, 빗썸 KRW, Binance 현물 USDT, Kraken 현물 USD.
기존 PublicMarket의 현물 universe 검사를 통과한 종목만 허용한다. 공개 일봉과 체결/호가 GET만 사용한다.

새 저장 경로:

`<root>/fast_wave/fast-wave-indicator-v1/<cohort>/observations.sqlite3`

기존 FAST 원장으로의 fallback/import는 없다. cohort를 바꾸면 새로운 검증 기록으로 시작한다.
관측 원본, 전일 기준, 변화량·속도·가속도, 정책값, 판정 이유와 수급 증거를 저장한다.
API 실패도 errors 테이블에 저장한다. 같은 시각의 관측값 덮어쓰기를 거부하고 최초 판정은 보존한다.
관측 이력은 자동 삭제하지 않으므로 장기 가동 전 일별 내보내기·보관기간을 추가해야 한다.

실행 예시(명시적으로 고른 1~5종목 관측):

```bash
python -m magi2.fast_wave_probe --venue upbit --symbols KRW-BTC KRW-ETH \
  --cohort prep-20260925 --root /data/magi2 --samples 3 --interval 60
```

나머지 거래소도 별도 프로세스에서 해당 현물 심볼로 실행한다. 이 도구는 전시장 TOP5 자동선정기가 아니다.
첫 조회 후 완료 일봉을 캐시해 이후 두 일봉만 요청한다(Kraken은 since 적용).
매수/매도, 계좌키, 텔레그램 발송, MAGI1 스키마 변경은 포함하지 않는다.

## 검증과 다음 연결점

- 수식 정답, 균일/불균등 간격, 전일 기준 불변, 미래/누락/중복/오래된 데이터 차단 테스트.
- 4개 거래소 응답 fixture 정규화·캐시·완료봉 수정·지연 응답 거부 테스트.
- 구 FAST 파일을 읽지 않는지, cohort 분리·재시작 보존과 관측→판정 기록 연결 테스트.
- 2026-09-25 작업 환경의 실제 공개 API 조회는 네 거래소 모두 ReadTimeout. 실연결 성공으로 간주하지 않는다.
- 운영 서버 환경에서 공개 API 응답과 관측 주기를 검증한 다음 전체 universe 순차 준비/수급 shortlist,
  최대 5종목 선정, 별도 PAPER 원장·진입/청산 연결을 구현해야 한다.
- PAPER 연결 시 포착 현재가+1틱 상한·10초 대기·추격 금지·매도 당일 재매수 금지·수수료/슬리피지를 유지하고,
  BTC 국면/동적 TP·SL/프로텍션은 개별 검증한다. 이 준비 버전에 반영됐다고 주장하지 않는다.
- 일별 매매평가에는 전략/cohort/거래소, 진입·청산 판단과 지표, 체결 비용, 순손익, 미체결·제외 이유를 연결한다.
