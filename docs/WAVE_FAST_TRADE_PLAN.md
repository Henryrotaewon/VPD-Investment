# WAVE / FAST 매매 준비안 v1

작성: 2026-09-19 KST. 설정 버전 `wave-fast-plan-v1`.
수치는 **사전 고정할 검증 가설**이며 최적화 결과나 수익 보장이 아니다.

## 이번에 준비한 것과 실제 운영의 경계

| 구분 | 현재 운영 | 이번 준비 |
|---|---|---|
| FAST | 4거래소 순위 탐색, 소수 후보 L1/체결 확인, 강한 매수세 알림, 5분 가격 반응 | 비용·예산·진입·청산·재진입 규칙 및 순수 판단 함수 |
| WAVE | 6거래소 공통 종목 관측, 선택된 사건의 시간 이동 대조 분석 | 독립 확산 확인 후 진입할 데이터 계약과 규칙 |
| MAGI3 | 실계좌 조회, 별도 VPD Shadow 기반 코드 | 이번 전략용 실제 주문·자동 모의매매 연결 없음 |

`magi2/trade_policy.json`이 설정 원본이며 `trade_plan.py`와 텔레그램 전략 설명이
함께 읽는다. `assess_entry`, `assess_exit`, `promotion_review`는 네트워크·원장·
주문 함수가 없는 순수 연구용 판단 함수다. `PAPER_CANDIDATE`는 함수의 판정값이며
모의체결 완료를 뜻하지 않는다. 운영 runner는 이 판단 함수들을 호출하지 않는다.
기존 VPD 모의투자, Shadow, MAGI1 수집·보관·분석 설정은 수정하지 않는다.

전략검증 → FAST, 전략검증 → WAVE → 전략 설명에서 준비안을 확인한다.
매매 가능성 화면은 계속 검증 전으로 표시한다. WAVE 사후 분석을 실시간
신호로 오인하거나 기존 FAST 알림에 가상의 체결을 붙이지 않는다.

## 역할과 우선순위

- MAGI1: 시장 관측·시간 품질·독립 충격/전파 자료. WHALE은 효과를 별도
  검증하는 추가 변수이며 큰 온체인 거래 하나를 매수 신호로 쓰지 않는다.
- MAGI2: 버전별 전략 조건·비용 평가·모의검증·전략별 주문 의도 생성 준비.
- MAGI3: 향후 공통 자금 예약·중복 방지·주문·체결 대사·청산·원장 담당.
- 구현 순서: FAST 체결 모의검증 → WAVE 독립 신호·대조군 → WAVE 확인 후
  체결 모의검증 → 전략·거래소별 검토. 초기 주문 검증 대상은 업비트 KRW.
  빗썸·바이낸스·크라켄의 공개 관측은 유지하고 실주문 확장은 각각 검증한다.

## 사전 고정할 핵심 규칙

| 항목 | FAST | WAVE |
|---|---|---|
| 포착 | 5분 +1% 이상, 상위 5위 또는 순위 +5 이상 | 시작 거래소에서 가격 이례성 z≥3, 거래량 z≥2 |
| 확인 | 후보별 15분, 직전 30초 고점 +0.10% 돌파 | 진입 거래소 외 2곳(시작+확인)에서 10초 내 같은 방향 |
| 매수 압력 | 최근 30초 이내 제한 체결 표본의 매수 주도 거래대금 ≥70%, 20건·5초 이상, 최근 체결 ≤3초 | 진입 시장 매수 주도 거래대금 ≥60%, 유효 표본과 시간 품질 확인 |
| 진입 시점 | 신선한 호가로 돌파 확인 후 | 확산 확인 **이후**, 3초 이내 신호·1.5초 이내 호가 |
| 목적지 확인 | 해당 거래소 자체 상승 | 목적지 15초 수익률 ≥+0.10%, 시장 공통요인을 뺀 충격도 양수 |
| 추격 상한 | 후보 선정 가격 대비 +1.00% | 목적지의 시작 충격 직전 가격 대비 +0.50% |
| 스프레드 | ≤0.10% | ≤0.10% |
| 왕복 비용 예산 상한 | 0.25% | 0.30% |
| 순익 목표 | +0.45% | +0.80% |
| 순손실 청산 신호 | −0.35% | −0.45% |
| 추적 청산 | 순익 +0.25% 도달 후 고점에서 0.15%p 반납 | 순익 +0.40% 도달 후 0.25%p 반납 |
| 진전 없음 | 45초 경과, 순익 고점이 +0.10% 미만 | 90초 경과, 순익 고점이 +0.15% 미만 |
| 최대 보유 | 180초 | 300초 |
| 신호 실패 | 돌파 기준선 아래로 3초 연속 후퇴 | 시작 시장 최근 3초 수익률 음수 + 목적지 매수 비중 50% 미만이 3초 지속 |
| 재진입 | 완전 청산 후 60초 + 새로운 30초 고점 재돌파, 같은 15분 사건 최대 3회 | 완전 청산 후 300초 + 새로운 독립 사건, 같은 사건 1회 |
| 동시 보유 | 최대 2종목 | 최대 1종목 |

진입 시 스프레드·추격·비용 기준을 모두 적용한다. FAST의 기존 **포착 기준**은
후보 선정 후 +2%까지 허용하지만, 이 **진입 준비안**은 +1%로 더 엄격하다.
포착 알림과 매매 기회는 같지 않다. 같은 종목을 VPD가 보유하거나 다른 전략의
미체결 주문이 있으면 초기 버전은 건너뛴다. 물타기·추가매수·교차 전략 중복 진입은 없다.

최고 순익은 당시까지의 실행 가능 매도 VWAP과 수수료로 산출한다. 미래 고점을
쓰지 않는다. 손절 우선 → 신호 실패 → 익절 → 추적 청산 → 시간 제한 → 진전 없음
순으로 평가한다. 손절은 주문 판단 기준이며 갭·지연·부분체결로 실제 손실은 커질 수 있다.
신호 실패 3초 지속 여부는 향후 상태 어댑터가 연속적인 유효 관측으로 계산해
`signal_failed`에 전달해야 한다. 현재 순수 함수는 그 상태를 수집하거나 유지하지 않는다.

## 자금과 반복 매매

- 1회 매수 수수료 포함 총자산 1% 이내. FAST+WAVE 합산 보유·미체결·수수료
  예약액은 **4.9% 이내**. FAST에 요청된 5% 미만 원칙을 지킨 보수적 공통 예산안이다.
- 총자산은 사전에 선언한 운용 계좌 범위의 완전한 원화 평가액. 범위를 사후에
  줄여 부분 평가를 완전한 값처럼 사용하지 않는다. 현재 계좌 평가가 불완전하면 진입 차단.
- 주식·가계 전체 재산이 아닌 해당 프로그램의 운용 총자산 기준. 기존 보유 코인을
  이 전략 자금 마련 목적으로 자동 매도하지 않는다. 실제 사용 가능한 예수금 내에서만 산정한다.
- 신규 전략 보유 위험액은 원가와 현재 평가액 중 큰 값 + 이미 낸 매수 수수료,
  미해결 주문은 전액 예약 유지. 자금 확인 5초 이내. 계좌·거래소 간 공유 예약은
  향후 MAGI3가 한 트랜잭션으로 담당한다.
- 총 3종목·KST 하루 합산 최대 15회. 5~6회는 성과를 위한 필수 횟수가 아니다.
- 일중 실현+실행 가능 평가손익(예상 청산 수수료 포함)이 일 시작 운용 총자산 대비
  −0.10%에 도달하면 신규 진입을 다음 KST 일자까지 중단. 미청산 포지션 관리는 계속.
- 3연속 손실은 신규 진입 30분 중단. 중단이 끝나고 미해결 주문이 없을 때 재개
  사건을 기록하고 연속손실 카운터를 리셋한다. 하루 손실 중단은 30분 뒤 풀지 않는다.
- 유효 매수/매도 호가 가격대의 양쪽 깊이 중 작은 쪽 금액의 10% 이하로 주문.
  참여율은 체결 보장이나 진정한 유동성 추정이 아니라 초기 보수적 상한이다.
- 최종 가격·수량을 거래소 단위로 내림/정규화한 뒤 최소 주문금액을 다시 검사한다.
  최소금액 미만이면 주문을 키워 억지로 맞추지 않는다.

`assess_entry`의 `equity_krw`는 현재 총자산(포지션 크기용), `daily_pnl_krw`는
현재 전략군의 위 정의 일손익이다. 일손실 분모는 `day_start_equity_krw`로 고정한다.
카운터·예약·휴식 상태의 내구성은 함수 호출자가 책임져야 하며 순수 함수만으로
중복 주문이나 재시작 복구가 해결되지 않는다.

## 비용과 주문 수명

진입 전 비용 예산 = 현재 스프레드 + 매수/매도 수수료 + 양방향 예상 호가 충격
+ 추가 지연 버퍼. 수수료는 `/v1/orders/chance`의 계좌·종목별 실제 값으로 확인한다.
테스트의 편도 5bps는 합성 입력이며 사용자 계좌 수수료를 확인했다는 뜻이 아니다.
예산 이내라는 사실만으로 양의 기대수익을 추정하지 않는다.

청산 순수익률은 `exit_VWAP × (1−매도수수료) / [entry_VWAP × (1+매수수수료)] − 1`.
VWAP에 스프레드·깊이 슬리피지가 이미 들어 있으므로 다시 차감하지 않는다.
부분체결은 체결된 수량별 수수료·원가를 원장에 반영한다. 포착 시점의 ask를
실제 진입 체결가로 소급해 쓰지 않는다.

향후 기본 주문은 가격 상한/하한을 정한 지정가 IOC다. 즉시 가능한 부분만 체결하고
나머지는 취소된다. 1초마다 판단하되 **상태가 변할 때만** 주문한다.
시세 조회 목표 주기와 주문 발송 주기를 동일시하지 않는다.

`WATCH → QUALIFIED → RESERVED → ENTRY_PENDING → OPEN → EXIT_PENDING → CLOSED → COOLDOWN`

이는 구현할 상태 계약이며 현재 라이브 실행 루프가 아니다. POST 결과가 불명확하면
`UNKNOWN`으로 남기고 identifier로 조회·대사한다. 재전송으로 새로운 주문을 만들지 않는다.
주문 ID는 계좌 전체에서 고유하게 유지한다. 부분 매수는 실제 체결 수량만 보유하고
잔여 취소 확인 전 예약을 풀지 않는다. 부분 매도는 남은 수량의 청산만 재평가한다.
청산 시각에 자료가 없으면 `EXIT_PENDING_DATA`; 마지막 가격으로 허구의 체결을 만들지 않는다.
재시작 시 원장·주문·잔고 대사를 마친 뒤 신규 진입한다. API 제한은 그룹별 공유
한도와 Remaining-Req/429 응답으로 제어한다. 확인 응답은 실제 체결과 구별한다.

## WAVE에 먼저 필요한 자료

기존 `wave-timeshift-catalog-v1`은 선택된 사건의 **사후 분석**이다. 5분 갱신,
완결 사건 기준 집계, 전역 쿨다운의 선택 편향이 있어 위 진입 판단에 직접 넣을 수 없다.
새 준비 계약 `wave-confirmed-setup-v1`은 다음을 갖춰야 한다.

1. 거래소별 독립 충격 트리거. 같은 종목이라도 먼저 잡힌 한 거래소만 저장하는
   선택 구조에서 분리한다. 종목·방향·관측 기간·UTC 사건 ID로 중복/겹침을 표시한다.
2. 사건 이전 30분에서 계산한 robust z(중앙값/MAD), 최소 300개 유효 과거 관측.
   가격 z는 동일 10초 수익률, 거래량 z는 동일 10초 거래대금의 `log1p` 기준.
   1.4826×MAD가 0이거나 표본 부족이면 미측정. 중첩 표본을 독립 사건 수로 세지 않는다.
   z≥3은 정규분포의 특정 오탐 확률이라는 뜻이 아니다.
3. 동일 시간의 BTC 및 거래소 공통시장 수익률을 사건 전 자료로 보정한 잔차,
   거래량·매수 주도 거래대금, 데이터 관측 범위와 공백. 공통뉴스 동조가 남을 수 있으므로
   이 조건만으로 거래소 간 인과관계를 주장하지 않는다.
4. origin/confirmation/decision/exchange/receive 시각과 시간 해상도. 목적지 가격의
   기준은 origin 직전 유효 호가. 종목 alias와 경제적으로 동일한 자산 여부를 정규화한다.
5. 진입 거래소 외 2곳의 확인은 동일 종목·매수 방향·10초 관측 길이여야 한다.
   분봉 결과를 초단위 확인에 섞지 않는다. 확인 후 3초 TTL이 지나면 건너뛴다.
6. WHALE 포함/제외는 같은 사건·같은 기간으로 비교한다. 소유자·거래소 유출입이
   확인되지 않은 raw 출력합계는 방향성 확증 자료로 사용하지 않는다.

현재 추가 수집은 시작하지 않았다. 구현 시에도 새 전 종목 호가 원본 보관을 만들지
않고 기존 피드의 짧은 메모리 구간·독립 사건 요약·표본화한 비사건 관측 범위를 사용한다.
현재 FAST L1만으로는 가상 IOC 깊이·부분체결을 평가할 수 없으므로 실제 진입 후보에
한해 얕은 호가 깊이를 일시 조회하고 체결/비용 요약을 저장하는 순서가 적절하다.

## 검증과 전환 판단

아래 값 역시 초기 승인 기준안이다. 기준을 충족해도 실주문이 자동으로 켜지지 않는다.

- 전략·거래소·고정 규칙 버전별 최소 14일/완료 왕복매매 200회/독립 사건 100개.
  그중 개발에 사용하지 않은 시간순 검증 구간 최소 7일/100회. 날짜와 건수 모두 충족.
- 개발·검증 구간 사이에 최소 최대 보유기간 5분을 비우고 같은 충격 군집은 한 구간에만 둔다.
  검증 결과를 보고 값을 바꾸면 새 버전으로 등록하고 새로운 미사용 구간을 확보한다.
- 비용 차감 OOS 평균순익 >0, 날짜/충격 군집을 고려한 95% 신뢰구간 하단 >0,
  OOS profit factor(총 순이익/총 순손실 절댓값) ≥1.2. 표본 부족이면 보류.
- 배정된 전략 자금의 최대 낙폭 ≤10%. 이는 승인 지표이지 손실 상한 보장이 아니다.
- 실제 수수료 1.5배, 양쪽 추가 슬리피지 각 5bps, 주문 지연 2초의 재생에서도
  평균 순익 >0. 지연은 미래 호가로 다시 체결해 평가하며 상수 수익률 차감으로 대체하지 않는다.
- 시간대·시장 변동성·유동성을 맞춘 비사건 대조군, 과도한 특정 종목 의존,
  신호 후 체결 가능률·잔량·미청산 손실·거래량 급감 시 손실도 함께 본다.
- 청산 실패/미해결 주문/누락 표본을 분모에서 없애지 않는다. 완료 거래 성적과
  별도로 전체 시도 대비 체결률·실패율·미청산 위험을 집계하고 미대사 0건 확인.
- 재시작·중복·미확인 POST·부분체결·최소주문·가격단위·수수료·현금 예약 테스트 통과.

`promotion_review`는 외부 검증 결과를 읽는 체크리스트일 뿐 통계 분석기가 아니다.
각 기준의 계산은 별도 검증 엔진이 만들어야 한다. READY_FOR_REVIEW도
`live_eligible=false`이며 계좌 권한 확인이나 실제 주문 테스트를 수행하지 않는다.

## 최소 로그

모든 기록: policy_version, strategy, episode_id, signal_id, venue, market,
origin/confirmation/decision/quote 시각, 조건 실측값·기준값·차단 사유.
진입/청산: reserved cash, client identifier, 요청가격·수량, 응답 상태,
체결가격·수량·수수료, 미체결/잔여, 지연, 청산사유, 순손익, 당시까지의 MFE/MAE.
상태 전환·거래 의사결정·체결 결과 중심이며 매초 전체 호가를 디스크에 누적하지 않는다.
각 재진입은 별도 signal_id, 같은 episode_id로 묶어 통계 표본 부풀림을 방지한다.
